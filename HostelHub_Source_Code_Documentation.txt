HostelHub - Smart Hostel Management System
Source Code Documentation
==========================================

PROJECT OVERVIEW
----------------
HostelHub is a Flutter-based mobile application for managing hostel operations.
It supports four roles: Student, Warden, Doctor, and Admin.
Backend: Firebase (Auth + Firestore + Messaging)

TECH STACK
----------
- Flutter (Dart)
- Firebase Auth, Firestore, Cloud Messaging
- Provider (state management)
- GoRouter (navigation)
- flutter_local_notifications
- google_fonts, intl, image_picker, url_launcher

import 'package:flutter/material.dart';
import 'package:firebase_core/firebase_core.dart';
import 'package:provider/provider.dart';
import 'app.dart';
import 'firebase_options.dart';
import 'providers/auth_provider.dart';
import 'providers/complaint_provider.dart';
import 'providers/resource_provider.dart';
import 'providers/service_provider.dart';
import 'providers/lost_found_provider.dart';
import 'providers/announcement_provider.dart';
import 'providers/parcel_provider.dart';
import 'services/auth_service.dart';
import 'services/firestore_service.dart';
import 'services/notification_service.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
  await NotificationService().initialize();

  runApp(
    MultiProvider(
      providers: [
        ChangeNotifierProvider(create: (_) => AuthProvider(AuthService(), FirestoreService())),
        ChangeNotifierProvider(create: (_) => ComplaintProvider(FirestoreService())),
        ChangeNotifierProvider(create: (_) => ResourceProvider(FirestoreService())),
        ChangeNotifierProvider(create: (_) => ServiceProvider(FirestoreService())),
        ChangeNotifierProvider(create: (_) => LostFoundProvider(FirestoreService())),
        ChangeNotifierProvider(create: (_) => AnnouncementProvider(FirestoreService())),
        ChangeNotifierProvider(create: (_) => ParcelProvider(FirestoreService())),
      ],
      child: const HostelHubApp(),
    ),
  );
}

==========================================
SECTION: KEY DESIGN DECISIONS
==========================================

1. ROUTER PATTERN
   GoRouter is created once in initState (StatefulWidget) with
   refreshListenable: authProvider so redirects fire on auth changes.
   Previously recreating router in build() caused login to not navigate.

2. ISLOADING INITIAL VALUE
   AuthProvider._isLoading starts as false so the login button is
   immediately interactive. It only becomes true during active
   login/register calls.

3. FIRESTORE QUERY ORDERING
   Queries using both .where() and .orderBy() require a Firestore
   composite index. To avoid this, we sort client-side after fetching:
     docs.sort((a, b) => b.createdAt.compareTo(a.createdAt));

4. RESOURCE SHARING FLOW
   Request-first model: students request items they need (with a
   needed-by deadline), other students offer to share with a specific
   meeting location and time. This is more practical than a
   "post what you have" model.

5. COMPLAINT CHAT
   Each complaint has a messages subcollection enabling direct
   student-warden communication per complaint thread.

6. IMAGE STORAGE
   Images are compressed and stored as base64 strings in Firestore
   (no Firebase Storage required). Limited to <700KB per image.

7. NOTIFICATION ARCHITECTURE
   - FCM token saved to user doc on login
   - Firestore listeners trigger local notifications for:
     parcels, announcements, emergency alerts, lost items, complaints
   - Works when app is in foreground; background handled by FCM
